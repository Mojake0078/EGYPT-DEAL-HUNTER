# EGYPT DEAL HUNTER

**منصة مصرية لاكتشاف العروض الحقيقية، ومقارنة الأسعار، وتحويل أفضل الصفقات إلى فرص تسويقية.**

المرحلة الأولى تركز على ثلاثة متاجر فقط:
- Amazon Egypt
- Jumia Egypt
- Noon Egypt

المتاجر الإضافية مثل Hyper One وCarrefour وGomla Market وB.TECH ستدخل في مراحل لاحقة بعد اختبار موصلاتها وجودة بياناتها.

## الهدف من المنتج

المشروع ليس مجرد صفحة تعرض أرخص سعر. الهدف هو بناء نظام يجمع الأسعار بانتظام، يحتفظ بتاريخها، يكتشف التخفيضات الحقيقية، ثم يخرج تقريرًا عمليًا يساعد على اتخاذ قرار تسويقي وربحي.

### مساران متكاملان

1. **Price Watch:** متابعة منتجات يحددها المستخدم، مقارنة العروض المتاحة، وحفظ سجل السعر والتنبيه عند انخفاضه.
2. **Deal Radar (نسخة أولية):** بحث تجريبي بعبارات منتجات محددة عبر Amazon Egypt وJumia وNoon، ثم تصدير النتائج إلى CSV وJSON. لا يزال الاكتشاف الشامل والجدولة والحفظ التاريخي قيد التنفيذ.

## ما يعمل حاليًا

- إضافة منتج لمتابعة سعره وهدفه السعري.
- البحث عن المنتج في المتاجر المفعلة.
- الاحتفاظ بسجل الفحوصات والأسعار.
- التمييز بين متاح، غير متاح، وحالة مخزون غير مؤكدة.
- استبعاد عروض المخزون غير المؤكد من اختيار أقل سعر مؤكد.
- تنبيهات انخفاض السعر وسجل تاريخي.
- لوحة ويب وواجهات API.
- وضع تجريبي ببيانات **مصطنعة** للاختبار فقط؛ لا تمثل أسعارًا حقيقية.

## Deal Radar: ما تم وما تبقى

**المنفذ في النسخة الأولية:**
- أمر تشغيل مستقل: `npm run deal-radar:scan`.
- ثلاث عبارات بحث أولية عبر Amazon Egypt وJumia وNoon.
- تقرير CSV وJSON يتضمن السعر بالجنيه، المتجر، رابط المنتج الأصلي، حالة المخزون، حالة المنتج إن ظهرت (مثل Refurbished)، ووقت الرصد.
- GitHub Actions ينفذ مسحًا مباشرًا ويرفع التقرير كـ Artifact قابل للتنزيل.
- كل نتيجة تحمل `INSUFFICIENT_HISTORY`؛ لا يتم الادعاء بأن السعر يمثل خصمًا مؤكدًا.

**المتبقي قبل اعتباره خدمة إنتاجية:**
1. توسيع مصادر الاكتشاف تدريجيًا مع حدود طلبات واحترام سياسات المتاجر.
2. حفظ كل لقطة سعر في قاعدة البيانات وربطها بالمنتج والمتجر.
3. مقارنة السعر الحالي بتاريخنا الفعلي، وليس بالسعر المشطوب فقط.
4. تصنيف الخصم إلى مؤكد من سجلنا، محتمل، أو غير مثبت.
5. إنشاء Excel/Google Sheets وجدولة مستقلة بعد التأكد من استقرار المصادر.
6. إضافة قائمة مراجعة قبل النشر على صفحة أو جروب Facebook؛ النشر التلقائي يأتي بعد ضبط الموافقات وسياسات المنصة.

**مهم:** النسخة الحالية لا تكتشف تلقائيًا كل المنتجات المعروضة في السوق ولا تعمل كل ساعة بعد. هي تجربة بحث أولية بعبارات منتجات محددة. Jumia قد يحجب عناوين IP الخاصة بمراكز البيانات، وAmazon قد يعيد أخطاء مؤقتة؛ لذلك نسجل فشل المصدر بوضوح ولا نخترع نتائج.

## حقول تقرير العرض المستهدف

- اسم المنتج والعلامة/الموديل إن أمكن.
- المتجر ورابط المنتج الأصلي.
- السعر الحالي، والسعر السابق المرصود، وتاريخ كل منهما.
- أقل سعر وأعلى/متوسط سعر في سجلنا خلال 30 يومًا متى توفرت بيانات كافية.
- نسبة التغير المحسوبة من سجل موثوق.
- حالة المخزون، وقت آخر تحقق، ومستوى الثقة.
- رابط أفلييت منفصل عن الرابط الأصلي، إذا كان البرنامج يسمح بذلك.

## نموذج تحقيق الدخل

راجع [بحث برامج الأفلييت وشروطها في مصر](docs/research/affiliate-monetization-egypt.md). برنامج Amazon Egypt نشط، لكن سياسته الحالية تمنع مواقع التتبع والتنبيه السعري ما لم توافق Amazon على استثناء؛ لذلك لن نفعّل روابط Amazon التابعة على موقعنا قبل موافقة مكتوبة.\n\n- **Affiliate:** استخدام روابط تتبع معتمدة من برنامج المتجر، بعد التحقق من قبول مصر وشروط العمولة وفترة الإسناد والفئات المستثناة.
- **Facebook:** نشر العروض على صفحة أو جروب مع الإفصاح عن الروابط التابعة، والاحتفاظ بالرابط الأصلي للمراجعة.
- **قنوات أخرى لاحقًا:** Telegram أو نشرة بريدية أو موقع عروض عام.
- لا نفترض أن مجرد وضع رابط منتج يحقق عمولة؛ يلزم رابط تابع صادر من برنامج أفلييت معتمد، وتُطبق شروط كل متجر.

## البنية التقنية

- React + Vite للواجهة.
- NestJS API وخدمة Checker.
- PostgreSQL لتخزين المتابعات وسجل الأسعار.
- RabbitMQ للأحداث والمهام.
- gRPC scraper sidecar.
- مكتبة جمع الأسعار موجودة محليًا داخل `libs/egypt-price-scraper` ويتم بناؤها من هذا المستودع؛ لا يحتاج بناء Docker إلى استنساخ مستودع المكتبة الخارجي.

## التشغيل المحلي

المتطلبات: Node.js 22+ وDocker.

```bash
cp .env.example .env
docker compose up -d --build --wait
```

واجهة الويب: http://localhost:8085  
واجهة API: http://localhost:3000

`SCRAPER_MODE=fake` هو الوضع الافتراضي ويستخدم بيانات تجريبية مصطنعة. لا تعرض بياناته باعتبارها عروضًا حقيقية. لتشغيل الجمع الحقيقي استخدم `SCRAPER_MODE=live`.

أوامر التطوير:

```bash
npm ci
npm run lint
npm run typecheck
npm test
npm run test:integration
npm run build
```

## مبدأ التوسع

المتاجر تضاف من خلال adapters منفصلة، وتظل قائمة المتاجر المفعلة محددة في إعدادات المرحلة. وجود adapter لمتجر في المكتبة لا يعني أنه مفعل في التطبيق.

## الأمان والامتثال

- لا نخزن بيانات دخول المتاجر.
- نستخدم حدودًا للطلبات والتوازي والتخزين المؤقت.
- نحتفظ بنتائج المتاجر المحجوبة أو الفاشلة كحالات واضحة، ولا نحوّل الفشل إلى «لا توجد عروض».
- نحترم شروط الاستخدام وملفات robots وسياسات برامج الأفلييت والنشر.
- لا نعلن عن خصم مؤكد من مقارنة سعرين لحظيين فقط.

## حالة التطوير

المشروع قيد التطوير. تغييرات إصلاح المخزون ونقل مكتبة الجمع وتحديد متاجر المرحلة الأولى موجودة على فرع العمل وPull Request للمراجعة؛ لم يتم دمجها في `main`.
